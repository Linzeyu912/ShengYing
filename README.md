# 声影 ShengYing

**将结构化剧本与数字资产转化为可控的对白、音效、配乐和镜头序列，最终合成为可迭代的视频成片。**

---

## 这是什么

「生影」是一个面向小说、短剧、动画与 AI 内容生产的视听制作引擎。

它承接「群像」产出的角色、场景、道具、故事线、剧本和分镜资产，将素材、对白、音效、配乐与视频生成任务组织为一套可追溯、可编辑、可复用的制作流程。

```text
小说 / 剧本 / 设定集
        │
        ▼
群像：实体抽取、故事梳理、资产与剧本准备
        │
        ▼
生影：声音制作、镜头生成、视频合成与成片交付
        │
        ▼
短剧 / 动画 / 宣传片 / 数字内容成片
```

群像解决“故事里有什么，以及应该怎么讲”；生影解决“这些内容如何被制作成有声音、有画面的作品”。

## 核心能力

- **剧本与镜头编排**：将场次、动作、台词与分镜组织为可执行的制作任务。
- **角色声音管理**：为角色建立可复用的音色、语言、语速、情绪与表演风格设定。
- **对白生成**：根据角色、台词、情绪和场景要求生成对白，支持试听、替换和版本比较。
- **音效与配乐制作**：生成或调用环境音、动作音效、打斗音效与背景音乐。
- **镜头生成**：结合角色、场景、道具和镜头描述，调用图像、视频或数字人模型生成镜头素材。
- **视听同步与合成**：将镜头、对白、音效、配乐和字幕按时间线合成，输出视频成片。
- **资产连续性控制**：在跨镜头、跨场景制作中保持角色形象、服装、场景、道具和声音的一致性。
- **多模型适配**：通过统一接口接入不同的语音、音效、音乐、图像和视频生成服务。
- **人工审核与版本管理**：支持在关键节点试听、预览、替换素材，并保留制作来源和版本记录。
- **项目化交付**：按项目、剧集、场次、镜头和素材管理制作过程，支持局部重生成。

## 与群像的协作关系

| 群像提供 | 生影使用方式 |
| --- | --- |
| 角色卡、外貌与性格设定 | 建立角色形象、声音设定与表演约束 |
| 场景卡、氛围与时间信息 | 生成场景画面、环境音与配乐方向 |
| 道具、技能与动作描述 | 生成镜头元素、动作音效和特效需求 |
| 故事线、场次与剧本 | 拆解为对白、镜头和时间线任务 |
| 分镜与导演资产包 | 编排视频生成、素材调用与合成顺序 |
| 提示词与资产引用 | 作为下游模型调用的受控输入 |

两个项目通过结构化资产包连接，而不是依赖不可追溯的自然语言复制粘贴。

## 制作流程

```text
导入群像资产包 / 编写剧本
        │
        ▼
场次与镜头拆解
        │
        ├── 音频制作：角色对白、环境音、动作音效、配乐
        │
        └── 视频制作：素材调取、镜头提示词、图像与视频生成
        │
        ▼
时间线编排与视听同步
        │
        ▼
人工预览、审核与局部重生成
        │
        ▼
导出视频、字幕、音频分轨与项目清单
```

## 核心概念

- **项目**：一部短剧、动画、宣传片或其他完整视听作品。
- **剧集**：项目中的单集或单个交付单元。
- **场次**：发生在同一时空条件下的一段叙事内容。
- **镜头**：最小的视频生成与剪辑单元。
- **角色声音**：角色固定的音色与表演参数，可在多个场次中复用。
- **音频片段**：对白、环境音、音效、音乐等按时间排列的声音素材。
- **数字资产**：来自群像或外部资产库的角色、场景、道具、参考图与模型配置。
- **制作版本**：同一镜头或音频片段的不同生成结果及审核状态。

## 首期目标

首个可运行版本优先完成以下闭环：

1. 导入群像导出的故事与资产包。
2. 创建剧集、场次、镜头和台词时间线。
3. 为角色配置并生成多情绪对白。
4. 为场次生成环境音、基础音效和背景音乐。
5. 调用视频生成模型产出镜头片段。
6. 将镜头、音频和字幕合成为预览视频。
7. 支持对单句对白、单段音效或单个镜头进行局部重生成。
8. 导出成片、字幕文件、音频分轨和项目清单。

## 软件搭建计划

> v0.1 · 2026-08-03 · 当前阶段：音频素材库搭建（VoxCPM 内置排期在素材库闭环之后）

### 总体架构

```text
┌────────────────────────────────────────────────┐
│  应用层（桌面端 / Web 端 UI）                     │
│  项目管理 · 时间线 · 素材浏览 · 试听 · 审核        │
├────────────────────────────────────────────────┤
│  服务层（本地后端，FastAPI）                      │
│  素材库服务 · 音色管理 · 对白生成 · 混音合成        │
├────────────────────────────────────────────────┤
│  模型适配层（统一接口，可插拔）                    │
│  TTS 适配器 ──► VoxCPM2（二期内置）              │
│  音效适配器 ──► 素材检索 + 生成式音效（二期）       │
│  音乐适配器 ──► 背景音乐（二期）                   │
├────────────────────────────────────────────────┤
│  数据层                                          │
│  SQLite 元数据库 + 文件系统素材仓 + 版本记录       │
└────────────────────────────────────────────────┘
```

设计要点：

- **模型适配层先做抽象**：TTS 接口统一定义，VoxCPM 是第一个内置实现，后续可无缝接入其他引擎。
- **素材与元数据分离**：音频文件走文件系统（不入 git），索引、标签、角色绑定关系走元数据与 SQLite，可备份、可版本化。
- **本地优先**：核心流程不依赖云服务。

### 模块一：音频素材库（当前进行中）

- **人物音色库**：可复用角色音色，跨剧集、跨场次绑定复用。每个音色含情绪样本与元数据（`voice.json`：性别、情绪覆盖、授权、版本、已知问题）。
- **音效库**：动作、打斗、转场等音效，按类别组织、可检索、可试听。（待补充）
- **环境音库**：多种氛围背景音，支持循环标记、多轨叠加与淡入淡出。（待补充）
- 规范：统一 48kHz WAV 存储；样本命名 `NN_情绪.wav`；素材授权信息强制登记。
- 素材现状与目录规范见 [assets/README.md](assets/README.md)。

### 模块二：VoxCPM 内置（计划，素材库闭环后启动）

将 OpenBMB VoxCPM（主力版本 VoxCPM2，Apache-2.0 可商用，2B 参数，FP16 约需 6–8 GB 显存）作为内置 TTS 引擎，推理服务以伴生进程方式由软件托管，对用户表现为"内置"。需要的能力：

- **声音克隆**：短参考音频零样本复刻（可控 / 极致模式）——现有音色库样本可直接作为克隆参考。
- **音色设计**：自然语言描述生成原创音色，快速扩充音色库且无版权风险。
- **上下文感知对白生成**：根据台词自动生成韵律与情绪。
- **多语言与方言**：30 种语言 + 9 种方言，为出海短剧预留。

集成路径分三步，同一适配接口封装、上层无感切换：

| 阶段 | 方案 | 说明 |
| --- | --- | --- |
| 验证 | `pip install voxcpm` 进程内直调 | 最快验证克隆与音色设计效果 |
| 服务化 | 官方 FastAPI 运行时 | UI 与推理解耦 |
| 生产 | vLLM-Omni / Nano-vLLM | 并发、流式输出、吞吐 |

### 模块三：对白生成流水线

台词 + 角色 + 情绪 → 音色解析（角色 → 库内音色）→ TTS 合成 → 试听审核 → 挂载时间线。支持单句重生成、历史版本比较、整场批量合成。

### 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 后端服务 | Python + FastAPI | 与 TTS 生态同语言 |
| 桌面端 | Tauri 或 Electron（M0 验证后定） | 跨平台 |
| 前端 | React + TypeScript + Tailwind | 时间线交互复杂 |
| 数据库 | SQLite | 本地单文件、零运维 |
| 音频处理 | ffmpeg + pydub / soundfile | 转码、混音、响度归一 |

### 风险与待决策项

1. **显存门槛**：VoxCPM2 FP16 需约 8 GB 显存；低配机器需量化或云端降级路径，验证后定。
2. **克隆音色合规**：参考音频必须取得授权，入库时强制确认授权声明。
3. **流式合成**：VoxCPM 流式输出存在 chunk 边界与重复播放的已知工程坑，实时试听需重点验证。
4. **桌面端框架**：Tauri vs Electron 未定，M0 期间做技术验证。
5. **音效 / 音乐生成模型**：二期选型，待素材库闭环后评估。
