# 声影 ShengYing · 软件搭建计划

> 版本：v0.1（草案）
> 日期：2026-08-03
> 范围：音频素材库（音色 / 音效 / 环境音）+ VoxCPM 能力内置

---

## 1. 需求理解

根据现阶段需求，声影的首个工程版本围绕两条主线展开：

1. **内置音频素材库**
   - **人物音色库**：可复用的角色音色资产，一个音色可跨剧集、跨场次绑定多个角色复用。
   - **音效库**：动作音效、打斗音效、转场音效、UI 音效等，按类别组织、可检索、可试听。
   - **环境音库**：多种氛围的背景环境音（街市、雨夜、战场、室内等），支持循环、分层叠加与音量控制。

2. **VoxCPM 能力内置**
   - 将 OpenBMB 的 VoxCPM（当前主力版本 VoxCPM2）作为内置 TTS 引擎，而非外挂服务。
   - 需要的核心能力：
     - **声音克隆**：短参考音频零样本复刻音色（可控模式 / 极致模式），用于"用真人音色建立角色声音"。
     - **音色设计**：用自然语言描述生成原创音色（无需参考音频），用于快速搭建音色库、且规避版权风险。
     - **上下文感知对白生成**：根据台词文本自动生成合适韵律与情绪，支撑多情绪对白。
     - **多语言与方言**：30 种语言 + 9 种方言，为出海短剧预留。
   - VoxCPM2 为 Apache-2.0 许可、可商用；2B 参数，FP16 推理约需 6–8 GB 显存，RTX 3060 级显卡即可本地运行。

## 2. 总体架构

```text
┌────────────────────────────────────────────────┐
│  应用层（桌面端 / Web 端 UI）                     │
│  项目管理 · 时间线 · 素材浏览 · 试听 · 审核        │
├────────────────────────────────────────────────┤
│  服务层（本地后端，FastAPI）                      │
│  素材库服务 · 音色管理 · 对白生成 · 混音合成        │
├────────────────────────────────────────────────┤
│  模型适配层（统一接口，可插拔）                    │
│  TTS 适配器 ──► VoxCPM2（内置默认）              │
│  音效适配器 ──► 素材检索 + 生成式音效（二期）       │
│  音乐适配器 ──► 背景音乐（二期）                   │
├────────────────────────────────────────────────┤
│  数据层                                          │
│  SQLite 元数据库 + 文件系统素材仓 + 版本记录       │
└────────────────────────────────────────────────┘
```

设计要点：

- **模型适配层先做抽象**：TTS 接口定义为 `synthesize(text, voice_ref | voice_prompt, emotion, speed) -> audio`，VoxCPM2 是第一个实现，后续可无缝接入其他引擎。
- **素材与元数据分离**：音频文件走文件系统（项目目录内），索引、标签、角色绑定关系走 SQLite，保证可备份、可版本化。
- **本地优先**：与 VoxCPM 本地部署的定位一致，核心流程不依赖云服务。

## 3. 模块设计

### 3.1 音频素材库（Asset Library）

**目录与元数据**

```text
assets/
├── voices/          # 人物音色（参考音频 + 音色配置）
│   └── <voice_id>/
│       ├── reference.wav      # 克隆用参考音频（可空，纯 Prompt 音色）
│       ├── voice.json         # 音色元数据（见下）
│       └── previews/          # 试听小样
├── sfx/             # 音效
│   └── <category>/<sfx_id>.wav
├── ambience/        # 环境音（支持 loop 标记、分层）
│   └── <scene_type>/<amb_id>.wav
└── library.db       # SQLite：标签、分类、授权信息、使用记录
```

音色元数据 `voice.json` 草案：

```json
{
  "voice_id": "v_chenmo_001",
  "name": "沉稳中年男声",
  "mode": "clone",                // clone | prompt | auto
  "reference_audio": "reference.wav",
  "reference_text": "……",          // 极致模式需要的参考台词
  "prompt": "低沉、平稳的中年男声",  // prompt 模式的自然语言描述
  "language": "zh",
  "bound_characters": ["char_003", "char_017"],
  "license": "original",           // original | licensed | cloned_authorized
  "created_at": "2026-08-03"
}
```

**功能清单**

- 素材导入（拖拽 / 批量）、自动转码（统一 48kHz WAV 存储，导出时可转 MP3/OGG）。
- 分类 + 标签 + 关键词检索；音效按时长、情绪、场景类型过滤。
- 内嵌播放器即时试听；环境音标记无缝循环点。
- 素材授权信息登记（来源、许可、是否可商用），呼应 README 的合规声明。

### 3.2 VoxCPM 集成层

**部署形态选择**

VoxCPM 有三种官方/社区部署方式，建议按阶段推进：

| 方案 | 接口 | 适用阶段 |
| --- | --- | --- |
| Python 包直调（`pip install voxcpm`） | 进程内 API | M1 验证期：最快跑通克隆与音色设计 |
| 官方 FastAPI 运行时 | `/tts/upload` 等 | M2 起：服务化，UI 与推理解耦 |
| vLLM-Omni / Nano-vLLM | OpenAI 兼容 `/v1/audio/speech` | M3+：需要并发、流式输出与吞吐时切换 |

三种形态背后用同一个 **TTS 适配器接口** 封装，上层无感切换。

**音色三模式**（与 VoxCPM 能力一一对应）

- **Clone 音色**：上传参考音频（或软件内录制）→ 入库 → 绑定角色。每次合成携带参考音频与参考文本。
- **Prompt 音色**：自然语言描述 → 生成原创音色 → 试听满意后"固化"为库内音色（保存生成参数与试听小样）。
- **Auto 音色**：根据角色卡（性格、年龄、人设）自动生成 voice prompt，作为零配置默认。

**内置方式**：VoxCPM 推理服务作为软件的子进程/伴生服务启动（本地 `http://localhost:<port>`），软件负责其生命周期管理（启动、健康检查、显存不足时降级提示），对用户表现为"内置"。

### 3.3 对白生成流水线

```text
台词 + 角色ID + 情绪标签 + 场景上下文
        │
        ▼
音色解析（角色 → 库内音色 → clone/prompt 参数）
        │
        ▼
VoxCPM 合成（可指定语速、情绪、语言）
        │
        ▼
试听 → 通过：入库并挂到时间线
     → 不通过：调参重生成，旧版本保留（版本比较）
```

- 单句粒度重生成，历史版本可追溯（对应 README 的"局部重生成"目标）。
- 批量模式：整场台词按角色分组连续合成，减少模型重复加载。

### 3.4 环境音与配乐

- **一期**：环境音以素材库调用为主，按场次氛围标签推荐；支持多轨叠加（如"雨声 + 雷声 + 远处车流"）与淡入淡出。
- **二期**：接入生成式音效/音乐模型，走同一适配层。

## 4. 技术选型建议

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 后端服务 | Python + FastAPI | 与 VoxCPM 生态同语言，适配成本最低 |
| 桌面端 | Electron 或 Tauri + Web 前端 | 跨平台；Tauri 更轻，Electron 生态更全，待决策 |
| 前端 | React + TypeScript + Tailwind | 时间线与素材浏览交互复杂，生态成熟 |
| 数据库 | SQLite（素材索引/项目数据） | 本地单文件、零运维、可随项目打包 |
| 音频处理 | ffmpeg + pydub / soundfile | 转码、切片、混音、响度归一 |
| TTS 引擎 | VoxCPM2（本地 GPU 推理） | Apache-2.0、48kHz、克隆+设计双能力 |
| 版本管理 | 文件快照 + 元数据版本表 | 音频二进制不适合 git，自建轻量版本记录 |

**硬件基线**：GPU ≥ 8 GB 显存（FP16 推理）；4–6 GB 可尝试 INT4 量化；无 GPU 时预留云端推理适配口，但不作为默认路径。

## 5. 开发里程碑

| 里程碑 | 目标 | 关键交付 |
| --- | --- | --- |
| **M0 工程骨架** | 仓库结构、前后端脚手架、SQLite schema、CI 基础 | 可启动的空壳应用 |
| **M1 VoxCPM 跑通** | Python 直调 VoxCPM2，验证克隆 / 音色设计 / 多情绪合成 | 命令行 Demo + 效果评估记录 |
| **M2 素材库** | 三类素材入库、检索、试听、授权登记；VoxCPM 服务化 | 素材库 UI + FastAPI 服务 |
| **M3 对白闭环** | 角色↔音色绑定、台词批量合成、试听与版本比较、时间线挂载 | 对白制作完整流程可用 |
| **M4 混音预览** | 对白 + 环境音 + 音效多轨混音，导出分轨与预览视频音频轨 | 一场戏的音频成片 |

M0–M1 不依赖 UI，可立即启动；M2 之后与群像项目的资产包协议对接进入联调。

## 7. 风险与待决策项

1. **显存门槛**：目标用户机器若无 8 GB 显存，需要量化方案或云端降级路径——M1 实测后定。
2. **克隆音色的合规**：参考音频必须取得授权，软件内需在克隆入库时强制确认授权声明。
3. **流式合成**：VoxCPM 流式输出在工程上有 chunk 边界与重复播放的已知坑，M3 做实时试听时需重点验证。
4. **桌面端框架**：Tauri vs Electron 未定，建议 M0 用一周做技术验证。
5. **音效/音乐生成模型**：二期选型（AudioLDM、Stable Audio 等）待素材库闭环后再评估。
